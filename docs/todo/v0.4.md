# v0.4 development todo

Boards survive restarts, access is controlled by signed links, and the socket contract is final: nothing after this version changes the wire protocol. Rough effort: four to five evenings.

## 1. Scope and access model

**In:** control channel, protocol v1, share links with edit/view roles, short-lived room tokens, Postgres persistence, epochs, server-side validation and limits, guest room expiry, chaos tests. **Out:** accounts and teams (0.8), snapshots and history UI (0.9), moderation UI (0.7).

**Access model until accounts exist**

| Who | Holds | Can |
| --- | --- | --- |
| Room creator | Edit link key, saved in localStorage | Edit, copy both links |
| Anyone with the edit link | Edit link key | Edit |
| Anyone with the view link | View link key | View, cursors visible, no edits |
| Anyone with only the room id | Nothing | Nothing: 403 |

- [ ] Write this table into ADR 0005 (access model) before coding; it changes the 0.1 behaviour where `GET /rooms/:id` was open

## 2. Control channel and protocol v1

Add channel 0 (control) and channel 3 (app) to `@planted/protocol`. Control and app payloads are CBOR (`cbor-x`), so Breached can decode them with `ciborium` in Rust.

- [ ] Frame header gains an optional `u32 seq` for control frames only (requests and replies are matched by it); yjs and awareness frames stay header + payload
- [ ] Control messages, each a Zod schema in `@planted/schema/protocol.ts`:

| Type | Direction | Payload |
| --- | --- | --- |
| `hello` (0) | C→S | `{ protocol: 1, token, clientName, stateVector? }` |
| `welcome` (1) | S→C | `{ role, roomEpoch, serverTime, limits: { maxFrameBytes, maxObjects } }` |
| `error` (2) | S→C | `{ code, message, fatal }` |
| `ping` (3) / `pong` (4) | both | `{ t }` |

- [ ] Close codes in one exported enum: 4400 bad frame or update, 4401 bad or expired token, 4403 role forbids it, 4404 room not found, 4409 epoch changed, 4413 doc limit reached, 4426 protocol too old, 4429 rate limited
- [ ] Handshake order: socket opens → client sends `hello` within 5 s (else close 4401) → server verifies token → `welcome` → then the 0.2 sync-1 / sync-2 exchange. Any yjs or awareness frame before `welcome` closes the socket with 4400
- [ ] Versioning: server accepts `protocol` 1 only for now; anything lower closes 4426 with `error { code: 'upgrade' }`, so old tabs show "Reload to update"
- [ ] App-level ping every 15 s replaces the native ping for liveness; two missed pongs → client reconnects, server terminates after 45 s silence
- [ ] App channel: types `ping-map` (1) and `kick` (2) defined now, handlers arrive in 0.6 and 0.7
- [ ] Codec tests for every new message, including CBOR round-trips and rejection of unknown fields

## 3. Share links and room tokens

Two kinds of secret: long-lived **link keys** (in share URLs, revocable) and short-lived **room tokens** (5-minute JWTs, sent in `hello`).

**Database** (new migration)

- [ ] `room_links`: `id` (12-char base62), `room_id` fk cascade, `role` (`edit` | `view`), `key_hash` (SHA-256 of the key), `created_at`, `revoked_at` null
- [ ] Store only the hash; the raw 32-byte key (base64url) exists only in the URL
- [ ] `rooms` gains `epoch integer not null default 1`

**Routes**

- [ ] `POST /rooms` now also creates one edit and one view link and returns `{ roomId, editKey, viewKey }` exactly once
- [ ] Share URL format: `/r/<roomId>#k=<key>`. The key lives in the fragment, so it never reaches server logs or `Referer` headers
- [ ] `POST /rooms/:roomId/token` with body `{ key }` → looks up the link by hash, checks not revoked → returns `{ token, role, expiresAt }`; wrong key → 403 with the same timing as a missing room (constant-time compare)
- [ ] `GET /rooms/:roomId` now needs `Authorization: Bearer <room token>`
- [ ] `POST /rooms/:roomId/links/rotate` (edit token required): revokes both links, creates new ones, returns the new keys, and closes every open socket with 4401 so holders of old links drop out
- [ ] Rate limit the token route: 30/min per IP

**Tokens**

- [ ] `jose` with HS256; secret `ROOM_TOKEN_SECRET` (at least 32 random bytes) in env, validated at boot
- [ ] Claims: `sub` = roomId, `role`, `lid` = link id, `iat`, `exp` = 5 min; `kid` header so you can rotate secrets later (accept current and previous)
- [ ] On `hello` the server re-checks that `lid` isn't revoked, so a rotated link can't sneak in with a still-valid token

## 4. Persistence and epochs

`apps/server/src/realtime/persistence.ts`, used by `Room`. The doc in memory is the source of truth while the room is loaded; Postgres is the copy that survives.

**Load**

- [ ] `manager.getOrCreate` becomes async and single-flight: concurrent joins to a cold room await the same `loading` promise, so a doc is never loaded twice
- [ ] Read `room_docs.ydoc`; if present, `Y.applyUpdate(doc, bytes, SERVER_ORIGIN)` before any socket gets `welcome`
- [ ] Log `room.loaded { roomId, bytes, ms }`

**Save**

- [ ] Debounce 2 s after the last update, with a max wait of 10 s, so a room that never goes quiet still saves every 10 s
- [ ] Save writes the full state (`Y.encodeStateAsUpdate(doc)`), not individual updates: one row per room, upsert, `version = version + 1`, `updated_at = now()`, and `rooms.last_active_at = now()` in the same transaction
- [ ] Never run two saves for one room at once; if a save is in flight, mark dirty and save again after it finishes
- [ ] On failure: log, retry with backoff (1 s, 2 s, 4 s … 30 s), keep the room loaded even if everyone leaves, and flag it in `/debug/realtime` as `unsaved`

**Flush**

- [ ] Before unloading a room: await a final save, then `doc.destroy()`. A room with unsaved changes is never unloaded
- [ ] Graceful shutdown: close sockets with 1001, then flush every dirty room in parallel with a 10 s overall timeout, then close the DB pool; log any room that didn't make it

**Epochs**

- [ ] `welcome.roomEpoch` comes from `rooms.epoch`
- [ ] Client remembers the epoch it last synced with; if `welcome` brings a different one, it throws away its local `Y.Doc` (and undo stack) and syncs fresh, instead of merging stale edits back in
- [ ] One way to bump the epoch for now: `POST /rooms/:roomId/clear` (edit token), which replaces the doc with an empty one, increments `epoch`, saves, and closes every socket with 4409 so everyone resyncs. Snapshot restore in 0.9 reuses the same path

## 5. Validation, roles and limits

CRDT updates can't be cleanly rejected after they're applied, so the server validates **after** applying and fixes problems with compensating changes. Bad actors get disconnected; good clients never hit this path.

**Validation**

- [ ] Board object schema becomes a discriminated union on `kind` in `@planted/schema` (only `stroke` exists today; 0.6 adds the rest)
- [ ] On every update from a socket, track touched object ids inside that transaction (`objects.observeDeep` filtered by `transaction.origin === conn`)
- [ ] After the transaction: `safeParse` each touched object; any failure → delete those objects in a `SERVER_ORIGIN` transaction, close the sender with 4400, log `{ roomId, ids, issues }`
- [ ] Allowed root types: `objects`, `meta`, plus `debug-items` in dev. A new unknown root type closes the sender with 4400 (root types can't be deleted, but they're never rendered or exported)

**Roles**

- [ ] Viewers: the server never sends them sync-1 (it doesn't need their state); any sync-2 or update frame from a viewer closes it with 4403
- [ ] Viewers may send awareness (their cursor is visible); the client sends `live: null` for them
- [ ] Role comes only from the verified token, never from anything the client claims

**Limits** (sent to the client in `welcome.limits`)

- [ ] Frames over 256 KB: closed by the WebSocket layer already (0.2)
- [ ] Per-socket token bucket: 200 frames/s (burst 400) and 512 KB/s; over the limit, drop awareness first, then close 4429 if yjs frames stay over for 2 s
- [ ] Max 20,000 objects: an update that pushes past it gets its new objects deleted compensatingly and the sender gets `error { code: 'object_limit', fatal: false }`
- [ ] Max 5 MB encoded doc: checked at every save; over it, the room turns read-only for everyone (editors get a non-fatal `error { code: 'doc_limit' }`) until something is deleted. A client-side "room is full" banner is enough for now
- [ ] Max 50 sockets per room; the 51st gets 4429

## 7. Client changes

**Keys and tokens**

- [ ] On `/r/$roomId`, read `#k=` from `location.hash`, store it in localStorage under `room:<id>:key` (try/catch), then strip the hash with `history.replaceState` so it doesn't linger in the address bar or screenshots
- [ ] No key in the URL or storage → "You need a link to open this board" page, no network calls
- [ ] "New room": store the returned edit key, navigate to `/r/<id>` (no hash needed)
- [ ] `RoomClient` takes `getToken: () => Promise<string>`; it fetches a fresh token before every `hello`, so reconnects never use an expired one

**Handshake and close codes**

- [ ] Send `hello` on open; start sync only after `welcome`; store `role` and `limits`
- [ ] 4401 → refetch the token once; if that returns 403, show "This link was revoked"
- [ ] 4409 → drop the local doc and undo stack, reconnect, toast "Board was reset"
- [ ] 4426 → banner "A new version is available" with a Reload button
- [ ] 4429 → back off at least 30 s; 4413 and non-fatal `error` frames → banner, stay connected
- [ ] 4403 or 4400 → stop reconnecting, show an error with the code (these mean a client bug or tampering)

**Read-only mode**

- [ ] Viewers: pen and undo disabled, cursor still shared, "View only" pill in the top bar
- [ ] Viewer client never sends sync-2 or updates (assert in dev builds)

**Share dialog** (edit role only)

- [ ] Two rows, edit link and view link, each with Copy; links built as `/r/<id>#k=<key>`. The dialog only has keys it was given at creation or that it holds; keep the view key in localStorage alongside the edit key
- [ ] "Rotate links" with a confirm: calls the rotate route, updates stored keys, explains that everyone else needs the new link
- [ ] "Clear board" (dev builds only for now) calls `/clear`
- [ ] Bots: `--key` flag, or create a fresh room and print both links on start
