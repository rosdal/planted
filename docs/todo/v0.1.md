## 2. packages/schema

The single source of truth for anything that crosses a boundary (HTTP now, WebSocket from 0.2). Server validates with it, web parses responses with it.
- [x] `pnpm --filter @planted/schema add zod` (add `zod` to the catalog first)
- [x] Layout: `src/ids.ts`, `src/api/rooms.ts`, `src/api/errors.ts`, `src/index.ts` re-exporting all
- [x] Room id: 16 random bytes, base62, always 22 chars:

```ts
export const RoomId = z
  .string()
  .regex(/^[0-9A-Za-z]{22}$/)
  .brand<'RoomId'>();
export type RoomId = z.infer<typeof RoomId>;
```

- [x] API DTOs:

```ts
export const CreateRoomResponse = z.object({ roomId: RoomId, createdAt: z.iso.datetime() });
export const GetRoomResponse = z.object({
  roomId: RoomId,
  createdAt: z.iso.datetime(),
  mapId: z.string().nullable(),
});
export const ApiError = z.object({ error: z.object({ code: z.string(), message: z.string() }) });
```

- [x] Error codes as a const union: `not_found`, `bad_request`, `rate_limited`, `internal`
- [x] Keep the `PROTOCOL_VERSION` constant from v0.0
- [x] Tests: valid id passes, 21/23 chars and non-base62 characters fail, DTO round-trips through `JSON.stringify` / `parse`
- [x] Rule for later: schema has zero runtime deps besides Zod, so Breached-side tooling can generate types from it

## 3. packages/db

Drizzle schema, migrations and a client factory. Deliberately no `users` table yet: better-auth generates its own in 0.8, and a hand-made one now would conflict.
- [x] `pnpm --filter @planted/db add drizzle-orm postgres` and `-D drizzle-kit`
- [x] `src/schema.ts`:

```ts
import { pgTable, text, timestamp, integer, customType } from 'drizzle-orm/pg-core';

const bytea = customType<{ data: Uint8Array }>({ dataType: () => 'bytea' });

export const rooms = pgTable('rooms', {
  id: text('id').primaryKey(), // 22-char base62 RoomId
  mapId: text('map_id'),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  lastActiveAt: timestamp('last_active_at', { withTimezone: true }).notNull().defaultNow(),
});

export const roomDocs = pgTable('room_docs', {
  roomId: text('room_id')
    .primaryKey()
    .references(() => rooms.id, { onDelete: 'cascade' }),
  ydoc: bytea('ydoc').notNull(),
  version: integer('version').notNull().default(0),
  updatedAt: timestamp('updated_at', { withTimezone: true }).notNull().defaultNow(),
});
```

- [x] `room_docs` stays unused until 0.4; it's here so the first migration matches the design (in 0.8 rooms gain a nullable `strat_id`)
- [x] `drizzle.config.ts`: `dialect: 'postgresql'`, `schema: './src/schema.ts'`, `out: './migrations'`, `dbCredentials.url` from `DATABASE_URL`
- [x] Scripts: `db:generate` (drizzle-kit generate), `db:migrate` (drizzle-kit migrate), `db:studio`; mirror them at the root with `pnpm --filter`
- [x] Generate the first migration, read the SQL, commit it. Migrations are append-only from now on
- [x] `src/client.ts`: `createDb(url: string)` returns `{ db, close }` using `postgres()` with `max: 10`; no global singleton, so tests can make their own
- [x] `src/index.ts` exports `createDb`, the schema and inferred types (`Room = typeof rooms.$inferSelect`)
- [x] `src/testing.ts`: `resetDb(db)` that truncates all tables, used by integration tests against `planted_test`

## 4. apps/server

Fastify 5, split into `buildApp(deps)` (pure, testable with `app.inject`) and `main.ts` (reads env, opens the DB, listens).

**Setup**
- [x] Deps: `fastify`, `fastify-type-provider-zod`, `@fastify/cors`, `@fastify/helmet`, `@fastify/rate-limit`, `close-with-grace`, `@plan`ted/schema, @planted`/db` (workspace); dev: `tsx`, `tsup`, `pino-pretty`
- [x] Layout:

```
apps/server/src/
  main.ts          // env → createDb → buildApp → listen, graceful shutdown
  app.ts           // buildApp({ db, env }) registers plugins + routes
  env.ts           // Zod schema for process.env, parse once, fail fast
  errors.ts        // AppError class + error handler → ApiError shape
  ids.ts           // newRoomId(): 16 bytes from crypto.getRandomValues → base62
  routes/health.ts
  routes/rooms.ts
  test/helpers.ts  // makeTestApp() against planted_test
```

- [x] Dev: `tsx watch --env-file=../../.env src/main.ts`. Build: `tsup src/main.ts --format esm --target node24`, which bundles the internal workspace packages (Node won't strip types inside `node_modules`, so running the TS source directly isn't an option)

**Behaviour**
- [x] Env schema: `DATABASE_URL` (url), `SERVER_PORT` (coerce number), `SERVER_HOST`, `WEB_ORIGIN` (url), `LOG_LEVEL` (enum); invalid env prints which key and exits 1
- [x] Logger: pino JSON in production, `pino-pretty` in dev; request id on every log line; never log request bodies
- [x] Zod type provider: `setValidatorCompiler` / `setSerializerCompiler`, so route schemas come straight from `@planted/schema`
- [x] CORS: only `WEB_ORIGIN`; helmet defaults
- [x] Error handler: `AppError(code, status, message)` → `{ error: { code, message } }`; Zod failures → 400 `bad_request`; unknown errors → 500 `internal` with the stack logged, never returned
- [x] `GET /health` → `{ ok: true, db: 'up' }` after `select 1`; 503 if the DB is down
- [x] `POST /rooms` → insert with `newRoomId()`, return 201 `CreateRoomResponse`; rate limit 10/min per IP on this route only
- [x] `GET /rooms/:roomId` → validate the param with `RoomId`, 404 `not_found` if missing, else `GetRoomResponse`
- [x] Graceful shutdown with `close-with-grace` (10 s): stop accepting, close Fastify, close the DB pool

**Tests** (Vitest, real Postgres, `resetDb` before each)
- [x] `newRoomId()` always 22 chars and passes `RoomId`; 10k ids, no duplicates
- [x] `POST /rooms` returns 201 and the row exists
- [x] `GET /rooms/:id` for a created room → 200; random valid id → 404; malformed id → 400
- [x] 11th `POST /rooms` in a minute → 429 in the `ApiError` shape
- [x] `/health` returns 503 when given a DB client pointed at a dead port
