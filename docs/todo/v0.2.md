# v0.2 development todo

Prove Yjs sync over your own Fastify WebSocket, with no drawing yet: two browsers and 20 bots edit a shared list and never diverge. State lives only in memory in this version; persistence is 0.4. Rough effort: three to four evenings.

**Built, with these departures from the plan below:** `decodeFrame` has a fourth error code, `frame_too_large`, and sync-2 frames may go up to the 5 MB doc limit instead of 256 KB, because a sync-2 carries the whole doc on first join and a 256 KB cap stopped any bigger doc from syncing; the doc hash hashes `Y.snapshot` (state vector + delete set) rather than the encoded update, whose layout can differ between converged docs; `r.$roomId.tsx` became a layout so the debug page can nest under it, with the room page moved to `r.$roomId.index.tsx`; `scripts/` is a workspace package, and the bots run in worker threads with `--rooms`, `--workers`, `--duration` and `--chaos-every` added, because one thread saturates before the server does; `/debug/realtime` also reports server RSS, CPU time and event-loop delay; `RoomProvider` goes offline on `pagehide` so a page in the back/forward cache doesn't hold a socket open. Results and the Hocuspocus comparison are in [ADR 0004](../adr/0004-custom-relay.md).

## 1. Scope and timebox

**In:** binary frames, Yjs sync, awareness, in-memory rooms, reconnect, room unload, fuzz and load tests. **Out (later versions):** control channel and tokens (0.4), persistence (0.4), roles (0.4), drawing (0.3).
- [x] Timebox half a day for a Hocuspocus comparison before writing the custom relay: run its server next to Fastify, connect the same debug page through its provider, note setup effort, bundle size and how hard custom framing and per-message role checks would be
- [x] Write ADR 0004 with the decision. Default unless Hocuspocus clearly wins: custom relay, because the design needs its own frame header, server-side validation of every update, and the same protocol from Rust (Breached)
- [x] Rest of this todo assumes the custom relay

## 2. packages/protocol

A new workspace with the frame codec, used by both server and web, so the two sides can never disagree on bytes. Pure functions, no I/O.
- [x] Create `packages/protocol` (`@planted/protocol`), deps: `yjs`, `y-protocols`, `lib0` (add all three to the catalog so server and web share one Yjs copy; two copies break `instanceof` checks)
- [x] Frame layout from the design doc, without `seq` for now:

```
byte 0   channel   1 = yjs, 2 = awareness   (0 control and 3 app arrive in 0.4)
byte 1   type      yjs: 0 sync-1, 1 sync-2, 2 update   awareness: 0 update
byte 2+  payload   raw bytes
```

- [x] Payloads use Yjs primitives directly, not `y-protocols/sync` (which adds its own type prefix):
  - sync-1: `Y.encodeStateVector(doc)`
  - sync-2: `Y.encodeStateAsUpdate(doc, remoteStateVector)`
  - update: the bytes from `doc.on('update')`
  - awareness: `encodeAwarenessUpdate(awareness, changedClients)`
- [x] API:

```ts
export const Channel = { Yjs: 1, Awareness: 2 } as const;
export const YjsType = { Sync1: 0, Sync2: 1, Update: 2 } as const;

export type Frame =
  | { channel: 1; type: 0 | 1 | 2; payload: Uint8Array }
  | { channel: 2; type: 0; payload: Uint8Array };

export function encodeFrame(f: Frame): Uint8Array;
export function decodeFrame(bytes: Uint8Array): Frame; // throws ProtocolError on unknown channel/type or < 2 bytes
```

- [x] `ProtocolError` class with a `code` (`short_frame`, `unknown_channel`, `unknown_type`) so the server can log and close with a reason
- [x] `MAX_FRAME_BYTES = 256 * 1024` exported; `decodeFrame` rejects larger input
- [x] Zero-copy: `decodeFrame` returns `bytes.subarray(2)`, never copies the payload

## 3. Server: rooms and the WebSocket route

**Files**

```
apps/server/src/realtime/
  room.ts          // Room: doc, awareness, conns, unload timer
  room-manager.ts  // Map<RoomId, Room>, getOrCreate, unload, stats
  connection.ts    // one socket: decode → dispatch, send helpers, heartbeat
  routes.ts        // GET /rooms/:roomId/ws
```

**Route**
- [x] Register `@fastify/websocket` with `maxPayload: MAX_FRAME_BYTES`
- [x] `GET /rooms/:roomId/ws`: validate `roomId`; check the room row exists in Postgres (close 4404 `room_not_found` if not); then `manager.getOrCreate(roomId).join(socket)`
- [x] Set `socket.binaryType = 'nodebuffer'` and wrap incoming `Buffer`s as `Uint8Array` views (no copy)

**Room**
- [x] `new Y.Doc({ gc: true })` and `new Awareness(doc)`; the server clears its own awareness state (`awareness.setLocalState(null)`) so it never shows as a user
- [x] On join: send sync-1 (server state vector) to the new socket
- [x] On sync-1 from a client: reply sync-2 with `encodeStateAsUpdate(doc, theirSV)`; also send the full awareness state of everyone else
- [x] On sync-2 or update: `Y.applyUpdate(doc, payload, conn)` (the connection is the origin)
- [x] `doc.on('update', (u, origin) => broadcast(update frame, except: origin))`, so the sender never gets its own update echoed
- [x] Awareness: `applyAwarenessUpdate(awareness, payload, conn)`; track which awareness client ids belong to each conn; `awareness.on('update')` broadcasts the changed clients to everyone except the origin
- [x] On close: `removeAwarenessStates(awareness, conn.clientIds, null)` so ghost cursors vanish immediately
- [x] Unload: when the last conn leaves, start a 60 s timer; a new join cancels it; on fire, `doc.destroy()` and remove from the manager
- [x] Wrap every `applyUpdate` in try/catch: on failure log `{ roomId, err }`, close that socket with 4400 `bad_update`, and do not broadcast

**Connection**
- [x] Heartbeat with native WebSocket ping every 15 s; terminate if no pong within 30 s (the app-level ping arrives with the control channel in 0.4)
- [x] `send()` skips sockets whose `readyState !== OPEN`; drops awareness frames when `bufferedAmount > 1 MB` (Yjs frames are never dropped)
- [x] Unknown or malformed frames: log the `ProtocolError` code, close 4400

**Observability**
- [x] Log `room.loaded`, `room.unloaded`, `conn.open`, `conn.close` with roomId, conn count and close code
- [x] Dev-only `GET /debug/realtime` returning `{ rooms, conns, docBytes per room }`; not registered when `NODE_ENV=production`
- [x] Graceful shutdown closes all sockets with 1001 `going_away` before Fastify closes

## 4. Web: RoomProvider

A plain TypeScript client class plus a thin React layer, so bots and tests can use the same client without React.

**Client** `packages/client/src/room-client.ts` (framework-free; the bots import it too, so keep DOM APIs out of it apart from an injectable `WebSocket` constructor)
- [x] Create `packages/client` (`@plan`ted/client), deps: @planted`/protocol`, `yjs`, `y-protocols` from the catalog; `apps/web` and `scripts/` both depend on it

- [x] Constructor `{ url, roomId, WebSocketImpl? }`; owns one `Y.Doc` and one `Awareness` for its whole life (survives reconnects)
- [x] Status machine: `connecting → syncing → synced → offline → connecting …`, emitted as events
- [x] On open: send sync-1 with the local state vector; reply to the server's sync-1 with sync-2; mark `synced` once both directions are done
- [x] Local `doc.on('update')` with origin not equal to the client → send update frame; while offline, edits just accumulate in the doc (Yjs merges them on resync, no queue needed)
- [x] Remote frames applied with `origin = this` so they aren't sent back
- [x] Awareness: send on local change; on reconnect, resend the full local state
- [x] Reconnect: backoff 250 ms × 2^n up to 10 s, ±50% jitter, reset after 10 s of stable connection; reconnect immediately on `online` and `visibilitychange` to visible
- [x] Close codes: 4404 → stop and emit `room_not_found`; 4400 → stop and emit `protocol_error`; anything else → reconnect
- [x] `destroy()`: close the socket with 1000, clear the local awareness state first so others see you leave instantly

**React** `apps/web/src/realtime/react.tsx`
- [x] `<RoomProvider roomId>` creates the client in a ref, destroys on unmount; safe under StrictMode's double mount (create in effect, not in render)
- [x] Hooks: `useRoomDoc()`, `useSyncStatus()`, `usePeers()` (from awareness, excluding self), `useYArray(name)` via `useSyncExternalStore`
- [x] Guest identity: name + random colour from an 8-colour palette, stored in localStorage (wrapped in try/catch), set as the awareness `user` field

## 5. Debug page

Route `/r/$roomId/debug`, linked from the room page in dev builds only.
- [x] Status pill: connecting / syncing / synced / offline, plus reconnect attempt count
- [x] Shared list: a `Y.Array<string>` named `debug-items`; input + Add, click an item to delete it, "Add 100" to stress it
- [x] Peers panel: name and colour of everyone in awareness, updating live
- [x] Stats: doc size (`encodeStateAsUpdate(doc).byteLength`), frames sent and received per second, last round-trip time
- [x] "Go offline" toggle that closes the socket and blocks reconnect, so you can make edits on both sides and watch them merge when you come back
- [x] Doc hash: a short hash of the encoded state shown on screen; two tabs in the same room must show the same hash once synced

## 6. Tests

**Codec** (`packages/protocol`)
- [x] Round-trip every channel/type through `encodeFrame` → `decodeFrame`
- [x] 0-byte, 1-byte, unknown channel, unknown type and oversized inputs each throw the right `ProtocolError` code
- [x] Property test (fast-check): any valid frame round-trips byte-identical

**Convergence fuzzing** (`packages/client`, no network)
- [x] `fast-check` property: create 2–8 `Y.Doc`s; run 50–500 random ops (insert, delete, move between two arrays, set map keys); route each update through a fake network that delays, reorders and duplicates; deliver everything; assert all docs encode to the same state and contain the same values
- [x] Same property with random disconnects: a peer stops receiving for a while, keeps editing, then resyncs via sync-1 / sync-2
- [x] Run 200 cases in CI, 10k locally via `FUZZ_RUNS=10000 pnpm test`; failing seeds printed and committed as regression cases

**Server integration** (real Fastify, `ws` package as client, Postgres from 0.1)
- [x] Two clients in one room: A inserts, B sees it within 100 ms; B never receives its own update back
- [x] Late joiner: A edits, then C connects and gets everything in its first sync-2
- [x] Unknown room id → close 4404; garbage frame → close 4400 and other clients are unaffected
- [x] A disconnects: B's awareness peers drop A within 1 s
- [x] Room unloads 60 s after the last client (use Vitest fake timers); rejoining before that keeps the doc
- [x] Server restart: clients reconnect on their own and their local state re-uploads (the doc survives in the clients even though the server lost it)

## 7. Bot load script

`scripts/bots.ts`, run with `pnpm bots --room <id> --count 20 --rate 5`.
- [x] Uses `@planted/client` with the `ws` package as `WebSocketImpl`
- [x] Each bot: random name, joins the room, sets awareness at 30 Hz (fake cursor wandering), inserts and deletes list items at `--rate` ops/s
- [x] Latency probe: one bot writes `{ t: Date.now(), by }` into a `Y.Map` every second; all others record `now - t` on receive
- [x] Prints every 5 s: connected bots, ops/s sent, frames/s received, p50 / p95 / max latency, doc bytes
- [x] `--chaos` flag: each bot randomly drops its socket every 30–90 s
- [x] On Ctrl+C: all bots compute their doc hash; script asserts every hash is identical and exits 1 if not

**Record in ADR 0004** (results table): rooms × bots, p95 latency, server CPU and RSS, for 1 × 20, 10 × 10 and 50 × 6 on your machine. These are the baseline numbers 0.3 and 0.7 compare against.

## 8. Done check

1. Open one room in two browsers (one normal, one private window); add, delete and "Add 100" in both: lists and doc hashes match
2. "Go offline" in A, edit in both, go back online: both merge, nothing lost, hashes match
3. `pnpm bots --count 20 --chaos` in the same room for 10 minutes while you keep editing in a browser; on Ctrl+C every hash matches
4. Restart the server mid-session: browsers show offline, reconnect within a few seconds, and the list is intact (it comes back from the clients)
5. Close a tab: the other tab's peers panel drops it within 1 s
6. Leave the room for 60 s: logs show `room.unloaded`; `/debug/realtime` shows it gone
