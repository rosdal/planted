# v0.5 development todo

Real maps and an original icon set, shipped as versioned data on a CDN. Most of the hours here are drawing, not code, so start the first map while 0.4 is still in progress. Rough effort: two to three evenings of code, plus 6–10 hours of drawing per map.

**Status (branch `feat/v0.5-content`).** The pipeline, catalogues, icon set, build and release tooling, server and client work are done and tested. Still open, because they need a person or an account:
- **The 3 real maps.** `maps/` holds three fictional practice maps (`practice-annex`, `-depot`, `-lighthouse`; 2, 3 and 4 floors), generated to exercise every step. Drawing real layouts needs your own walkthroughs (section 4), so those boxes stay open.
- **R2.** The bucket, custom domain, CORS and repository secrets need the Cloudflare account; `content-release.yml` and `content:release` are written but have never run against R2 (done check 4).
- **Review by hand:** a teammate on callouts and wall kinds (done check 3), the lawyer question, and stack view, which is 0.6.

**Where this differs from the todo**
- The migration is `0002_content_version`: the journal ended at `0001`.
- Rooms load their pinned version from `GET /rooms/:id` (the row holds the same `mapId` and `contentVersion` the server wrote into `meta`), so floor art starts loading before the socket syncs.
- Room ids in `map.json` are `room:<floor>:<slug>`, so a slug may repeat across floors; objectives' `data-room` names the slug on their own floor.
- Extracted rooms drop points within 0.1 units of a straight line after sampling curves at 1 unit; otherwise a straight wall ships as hundreds of points.
- Sprite symbols are `icon-<iconId>`, not `<iconId>`, so they can't collide with other ids in the page. The sprite is rebuilt from an allowlist before it touches the DOM.
- Thumbnails render the art on the board's dark background with resvg, then `sharp` encodes the WebP; resvg only writes PNG.
- Floors are validated against the content bundled with the server, not the room's pinned version; floor ids don't change between seasons, and 0.9's migrations cover the case where one does.
- Rooms made before 0.5 have no map; they keep the old test floor instead of failing to load.
- `ROOMS_PER_MINUTE` (default 10) makes the room creation limit configurable, because the e2e suite now creates more rooms than that.
- `/dev/icons` uses stand-in slot colours until 0.6 settles the slot palette.
- Done check 7: 1.76 s on Fast 4G, 4.05 s on Lighthouse's slow-4G profile; see [docs/perf/v0.5.md](../perf/v0.5.md).

## 2. Content model

Zod schemas in `packages/content/src/schema/`; every JSON file is validated against them in CI. Coordinates are in map space (0..1) like the board.

**`maps/<mapId>/map.json`**

```ts
export const MapData = z.object({
  id: z.string(), // 'clubhouse'
  name: z.string(),
  contentRev: z.string(), // season tag of this layout, e.g. 'y11s3'
  floors: z.array(
    z.object({
      id: z.string(),
      label: z.string(),
      order: z.number(), // 'b', '1f', '2f', 'roof'
      art: z.string(), // hashed filename after build
    }),
  ),
  sites: z.array(
    z.object({
      id: z.string(),
      name: z.string(),
      floorId: z.string(),
      objectives: z.array(z.object({ label: z.string(), at: Vec2, roomId: z.string() })),
    }),
  ),
  rooms: z.array(
    z.object({
      id: z.string(),
      floorId: z.string(),
      callout: z.string(),
      polygon: z.array(Vec2).min(3),
    }),
  ),
  walls: z.array(
    z.object({
      id: z.string(), // stable across seasons: 'wall:2f:gym-north'
      floorId: z.string(),
      from: Vec2,
      to: Vec2,
      kind: z.enum(['soft', 'reinforceable', 'hard', 'outer']),
    }),
  ),
  hatches: z.array(z.object({ id: z.string(), floorId: z.string(), at: Vec2 })),
  openings: z.array(
    z.object({
      id: z.string(),
      floorId: z.string(),
      from: Vec2,
      to: Vec2,
      kind: z.enum(['door', 'window', 'vault']),
    }),
  ),
  spawns: z.array(
    z.object({
      id: z.string(),
      name: z.string(),
      side: z.enum(['attack', 'defence']),
      floorId: z.string(),
      at: Vec2,
    }),
  ),
});
```

## 3. Authoring pipeline

You draw in a vector tool; a script turns named layers and element ids into `map.json`, so nobody hand-edits coordinates.

**SVG conventions** (one SVG per floor, `maps/<mapId>/src/<floorId>.svg`, viewBox 0 0 4096 4096)

| Layer (group id) | Contains                                                   | Element id pattern                                     |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| `art`            | Everything visual: floor fill, wall strokes, stairs, props | anything                                               |
| `rooms`          | One closed `path` or `polygon` per room                    | `room:<slug>` with `data-callout="Gym"`                |
| `walls`          | One `line` per wall segment                                | `wall:<floor>:<slug>` with `data-kind="reinforceable"` |
| `hatches`        | One `circle` per hatch                                     | `hatch:<floor>:<slug>`                                 |
| `openings`       | One `line` per door, window, vault                         | `door:…`, `window:…`, `vault:…`                        |
| `sites`          | One `circle` per objective                                 | `obj:<site>:<A or B>` with `data-room`                 |
| `spawns`         | One `circle` per spawn                                     | `spawn:<side>:<slug>`                                  |
- [x] A template SVG with all layers, a legend and the style guide colours, in `packages/content/templates/floor.svg`
- [x] Inkscape keeps `id` and `data-*` attributes; if you use Figma, export with ids enabled and keep a note of the plugin settings in the README

**Extractor** `packages/content/scripts/extract.ts`
- [x] Parse with `svgson`; apply group transforms so coordinates are absolute; flatten paths to polygons (`svg-path-parser`, sample curves at 1 unit)
- [x] Convert 0..4096 to map space and round to 5 decimals
- [x] Merge all floors plus `maps/<mapId>/meta.json` (name, floor labels and order, site names) into `map.json`
- [x] Export the `art` layer alone as the floor's display SVG; strip all data layers from it
- [x] Errors are human-readable with the element id: "wall:2f:gym-north has no data-kind"

**Validation** (`pnpm content:check`, also in CI)
- [x] Schema-valid; ids unique per map; room polygons closed and non-self-intersecting; every wall endpoint within 0..1
- [x] Every objective's `data-room` exists on the same floor
- [x] **Wall id stability:** compare against the last released `map.json`; a removed or renamed wall or hatch id fails the check unless it appears in `maps/<mapId>/migrations/<rev>.json` (the 0.9 migration format, stubbed now as `{ from: to | null }`)

**Release**

- [x] GitHub Action on tag `content-v*`: build, `content:check`, upload with `@aws-sdk/client-s3` (R2 is S3-compatible); hashed files `Cache-Control: public, max-age=31536000, immutable`
