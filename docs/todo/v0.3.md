# v0.3 development todo

A real board on top of the 0.2 relay: pan, zoom, draw with a pen, see everyone's cursors and strokes live. Ends at gate 1 from the design doc: 10 users at 60 fps with no lost strokes. Rough effort: four to six evenings.


**Built, with these departures from the plan below.** Gate 1 is not passed yet; status and numbers are in [docs/perf/v0.3.md](../perf/v0.3.md). The final measurement and the hand checks (items 3 and 4) are still to do, and `v0.3.0` isn't tagged.
- **Floor art:** parsed into Pixi `Graphics` (`parseAsGraphicsContext`) instead of a texture: vectors stay sharp at 8×, where a 4096 px texture would blur. Pixi's SVG parser ignores `stroke-width` on an element that doesn't also set `stroke`, so every element in `test-floor.svg` sets its own.
- **Board structure:** the Pixi engine lives in `board/board.ts`, with the floor and grid in `render/map.ts`; `BoardCanvas.tsx` is a thin host.
- **Render groups:** `world`, the live layer, and 8 × 8 spatial stroke tiles are Pixi render groups, and culling happens per tile, not per stroke. Measuring showed a single stroke container re-uploading every stroke's vertices on each change.
- **Ids and schema:** ids come from a shared `base62Id` in `@planted/schema`, which `newRoomId` on the server now uses too. `StrokeObject` also rejects a stroke with zero points.
- **Awareness:** cursor and live stroke go out together in one awareness frame at most every 33 ms, with live points rounded to 1e-5. A peer's live stroke lingers up to 1 s after its `live` goes null, which bridges the awareness/doc race and also fades a cancelled stroke.
- **Identity:** no longer saved automatically. The first visit opens the dialog; Escape keeps a per-tab "Guest 1234" without saving it. `usePeers` only changes when someone joins, leaves or renames: it used to re-render the page on every cursor move.
- **Undo:** undo and redo are ignored while a stroke is being drawn.
- **Overlay:** also shows zoom and dropped frames (over 1.5× the median frame time). With `deltaMS` jitter at 60 Hz, p95 sits at ~17.0 ms even with no drops.
- **Bots:** `--mode draw` also checks for lost strokes: objects ≥ bot strokes − undos, equal when only bots drew.
- **E2E:** runs on ports 5198/5199, one worker, against the dev server, plus an Escape test and a first-visit dialog test; CI installs Chromium and runs `pnpm e2e`.
- **Measurement:** `scripts/gate1.ts` automates it with two scripted "humans" in real Chrome windows. People are still needed for the feel checks.

## 4. Stroke model and scene binding

**Model** (in `@plan`ted/schema, builders in @planted`/client/board.ts` so the web app and bots write identical objects)
- [x] `doc.getMap('objects')`: `Y.Map<id, Y.Map>`; one nested `Y.Map` per object so later tools can change single fields
- [x] Stroke fields:

```ts
export const StrokeObject = z.object({
  kind: z.literal('stroke'),
  floor: z.string(), // 'test-1' for now
  phase: z.string().nullable(), // null until 0.6
  colour: z.string().regex(/^#[0-9a-f]{6}$/i),
  width: z.number().min(0.0002).max(0.02), // map units, so it scales with zoom
  points: z
    .instanceof(Uint8Array) // Float32 pairs in map space
    .refine((b) => b.byteLength % 8 === 0 && b.byteLength <= 4096 * 8),
  by: z.string(), // awareness user name at the time
  at: z.number(), // Date.now()
});
```

- [x] Ids: 12-char base62 from the same generator as room ids; the live stroke and the committed object share the id (see pen tool)
- [x] Points stay immutable after commit; erasing in 0.6 deletes the whole object

**Binding** `apps/web/src/board/scene-store.ts`
- [x] `objects.observeDeep(events)`: collect affected top-level ids (`event.path[0]` for nested changes, `event.changes.keys` for adds and deletes) into a dirty set
- [x] Flush the dirty set once per animation frame from the Pixi ticker, never inside the Yjs callback (a 100-stroke undo becomes one flush)
- [x] Per id: parse with `StrokeObject.safeParse`; on success create or rebuild the `Graphics`; on failure skip it and `console.warn` once (server-side validation arrives in 0.4); deleted ids destroy their `Graphics`
- [x] SceneStore talks to a small `SceneSink` interface (`create`, `update`, `remove`) instead of Pixi directly, so it can be unit-tested with a fake sink
- [x] Initial load: build all existing objects in one pass after the first sync

**Rendering**
- [x] Stroke `Graphics`: `moveTo` the first point, then quadratic curves through the midpoints of successive points (smooth, no extra points stored); `stroke({ width, color, cap: 'round', join: 'round' })`
- [x] Single-point strokes (a tap) render as a filled circle
- [x] Mark stroke `Graphics` `cullable = true` and register Pixi's culler extension, so off-screen strokes cost nothing

## 5. Pen tool

**Input**
- [x] `pointerdown` (primary button, not while Space is held) → `setPointerCapture`, start a stroke with a new id
- [x] `pointermove` → read `event.getCoalescedEvents()` (falls back to the event itself), convert each to map space, append to a local `number[]`
- [x] Drop points closer than 0.75 screen px to the previous one before storing
- [x] `pointerup`, `pointercancel`, `lostpointercapture` → commit; `Escape` while drawing → cancel, nothing committed
- [x] Ignore right-click and pen-eraser buttons for now

**Local live stroke**
- [x] Draw the in-progress stroke into `liveLayer` every frame from the local buffer: zero network in the loop, so it feels instant
- [x] Rebuild only the tail segment each frame (keep the committed part of the live `Graphics` as is) once strokes pass \~500 points

**Remote live strokes**
- [x] Awareness field `live: { id, colour, width, points: number[] } | null`, sent at most every 33 ms (30 Hz) while drawing
- [x] Send the stroke-so-far simplified with RDP at a small epsilon (0.5 screen px), capped at the last 1,000 points, to keep awareness frames small
- [x] Receivers draw other users' `live` strokes in `liveLayer`; if `objects` already has that id, skip the live version (no double drawing, no flicker on commit)

**Commit**
- [x] Simplify with Ramer–Douglas–Peucker; epsilon is 1 screen px converted to map units at the current zoom (`1 / (scale * WORLD_SIZE)`)
- [x] Pack points into a `Float32Array` and store its bytes as `Uint8Array`
- [x] `doc.transact(() => objects.set(id, strokeMap), LOCAL_ORIGIN)`, then set awareness `live` to null in the same tick
- [x] Width: 3 screen px at the zoom the stroke started at, stored in map units
- [x] Colour: the user's awareness colour for now (colour picker in 0.6)

## 6. Cursors, identity and undo

**Remote cursors**
- [x] Awareness `cursor: { x, y } | null` in map space; send on pointer move at most 30 Hz, only if it moved; `null` on `pointerleave` and when the tab is hidden
- [x] Render in `cursorLayer` (screen space): arrow + name tag in the user's colour; position recomputed with `worldToScreen` every frame so it tracks pan and zoom

- [x] Fade a cursor out after 10 s idle; remove when its awareness state disappears

## 8. Done check: gate 1

All of these on the reference machine, production build:
1. 2 humans + 8 bots draw for 5 minutes: p95 frame time ≤ 16.7 ms (60 fps), no frame over 50 ms after the first second
2. No lost strokes: at the end every client's `docHash` matches and bots' committed-stroke counts equal the object count (minus undos)
3. Your own strokes appear under the pointer with no visible lag; remote strokes grow live and don't flicker on commit
4. Cursors track smoothly through pan and zoom; a closed tab's cursor disappears within 1 s
5. Undo only ever removes your own strokes, verified by the E2E test and by hand
6. Zoom from fit to 8×: map and strokes stay sharp, panning stays at 60 fps with 2,000+ strokes on screen
7. `pnpm check` and Playwright pass in CI; `docs/perf/v0.3.md` committed with the numbers; tag `v0.3.0`

**If the gate fails**, fix it inside 0.3 before starting 0.4. Likely suspects in order: flushing inside Yjs callbacks, rebuilding every stroke on each change, `Text` instead of `BitmapText`, awareness frames too large, and too-high renderer resolution on HiDPI screens.
